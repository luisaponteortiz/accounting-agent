# Implementation decisions

- **D-001 — Product scope (November 14, 2026):** General Accounting Agent OS for the full accounting cycle. Bird Bowl is a client implementation; card preparation is the first test workflow. The user's correction supersedes any card-only product framing. No unrelated SS business-development agents.
- **D-002 — Local execution stack:** Python standard library, SQLite, static HTML/JS for this executable slice. Observed Python 3.9.6; Node, Docker, uv and proposed Python libraries unavailable. Avoid a dependency-installation prerequisite while producing testable software. Material deviation from default stack is explicit; no PostgreSQL/production claims. M0–M5 as a whole are not complete.
- **D-003 — Modules:** generic workflow runner and capability registry first; demonstrate card preparation, journal validation and close readiness. AP/AR/reconciliations/reporting/analysis remain explicit deferred modules.
- **D-004 — Client facts:** unconfigured real Bird Bowl profile and a distinct fictional demo profile. No actual chart/mappings/receipt policies asserted. Demo policy may authorize internal synthetic preparation only.
- **D-005 — Conservative review:** immutable artifacts, separate independent human demo decisions, current-generation checks; any client input/config revision invalidates prior approvals. Review only authorizes reviewed preparation export, never posting or close.
- **D-006 — Autonomy:** scoped synthetic mandates, deduplicated simulated recurring events and durable background worker. No live schedules, credentials, network/model calls, deployments or ledger writes.

- **B1/T-02 — Vendor identity:** NFKC + casefold preserves Unicode alphanumerics and accents; empty normalized aliases are rejected and empty descriptors never match. Duplicate keys separate known-vendor identities from descriptor fallbacks. Non-Latin and accent regressions added; ambiguous aliases remain blocked with no proposed category.
- **B1/T-03 — Review independence:** Trusted Actor records now distinguish human/service. Hashed artifact contributors include the enqueue actor, committing worker, mandate issuer, scoped input suppliers and profile registrant. All review decisions require a non-contributing human reviewer; actor-name prefixes grant or deny nothing. Old artifacts lacking contributor provenance fail closed for new decisions. Synthetic mandates require a human preparer; independent mandate/policy activation remains Batch 2, not implied by this change.
- **B1/T-04 — Occurrences versus runs:** Schema migration 2 moves recurrence uniqueness to durable occurrences, links attempts, and adds a database unique partial index permitting one completed run per occurrence. Stale held attempts can be re-dispatched; unfit mandates are held independently without rolling back other work or the clock. Missed slots are explicit skipped_no_catch_up records. Synthetic windows are bounded to 10,000 slots to bound skip recording. Existing immutable evidence/artifacts/decisions/audit are never rewritten.
- **B1/T-05 — Durable accounting periods:** Migration 3 adds period records/history, immutable source-period bindings and frozen run references. Human independent reviewer operations open/lock/reopen periods; locks do not change knowledge generation or reviewed work. Dated inputs are assigned by their explicit fixture date; sources without a configured period are quarantined as UNASSIGNED_ACCOUNTING_PERIOD, not prepared under another month. Undated documents require explicit packet period or exactly one configured period. Late locked-period evidence is retained but not admitted until an audited reopen.
- **B1/T-05 deliberate test/API changes:** The original period field was removed from profiles. Seed/reviewer harnesses now open periods explicitly; FV-J07 verifies locked dispatch refusal via lock_period; FV-J05 verifies quarantine rather than wrong-period preparation. Original teaching TX-008 is now a source-period exception until October opens, so the initial artifact count changes 21→20 (12→11 card items). Original wrong-period journal/derived V-10 tests assert own-period validation/quarantine. No blocker was weakened and no source was discarded. Original supplied scripts remain under review/original/; exports/FABLE_REVIEW_RESPONSE entry points forward to the maintained canonical runner.
- **B1/T-06 — Relevant input lineage:** Capability declarations now scope source kinds, profile sections and bound-period lookback. Runs persist that manifest; handlers receive only declared input kinds/sections. Receipt changes no longer invalidate journals, and journal documents do not invalidate cards. Accounting code lineage hashes core.py/modules.py and capability versions, excluding transport/CLI/UI. Invalidation remains conservative within each workflow/period population; per-item optimization/finalized packages are not claimed. Calendar-date period routing is explicit synthetic recurrence behavior; real client period/freshness rules remain Batch 2.
- **B1/T-07 — Governing artifacts and decisions:** Migration 5 links multiple runs to immutable artifacts. Envelopes cite dependency content hashes, not row IDs; byte-identical current preparations are reused. The newest completed linked preparation governs each workflow/period/item. State/export contain one item review state and all immutable links/history; non-governing decisions fail closed. Repeated decisions return 409; contradictory independent reviewers create disputed, never last-write-wins approval. Resolution is explicit resolve_approve/resolve_reject by a third non-contributing human reviewer in the synthetic service; real resolution authority remains unconfigured. Approved→revoke remains append-only.
- **B1/T-07 compatibility:** Run membership is now artifact.run_ids; artifact.run_id remains its immutable originating run. Existing helpers and reviewer harness query membership rather than assume a new artifact row per execution. Legacy profile removal of only the retired period field is accepted as migration cleanup without inventing a new accounting-policy version; any substantive change still requires a new version.
- **B1/T-07 migration hardening:** Concurrent startup exposed SQLite journal_mode lock behavior. Startup now serializes in-process schema bootstrap, rechecks versions under writer locks, and bounds busy journal-mode retries. Concurrent migration/foreign-key/immutable-byte tests verify this; no workflow retry authority was expanded.

- **C-04 — Historical authorship:** Interim independence includes suppliers of all versions of every manifest input identity and all profile registrants, plus enqueuer, worker and mandate issuer. - **C-03 — Provenance separate from identity:** Migration 6 adds immutable artifact_contributors rows for every linked run. New content hashes exclude contributor identity; legacy envelopes/hashes remain byte-for-byte unchanged and their contributor lists remain authoritative. Review uses the union. - **C-01 — Locked-origin moves:** New source versions inspect prior admitted period lineage. Moves from a locked origin are quarantined as SOURCE_MOVED_FROM_LOCKED_PERIOD and enter no destination population. Move history/audit bind both periods and earlier approval evidence. Reopening the origin re-evaluates the newest quarantined transaction/support versions; the old period becomes stale before destination work can govern. Migration 7 retains append-only move history.
- **N16 behavior:** An exact policy/input reversion can restore a prior input-bound review; that is recorded behavior, not a new decision or authorization. Effective-dated policy changes are addressed under T-09.
- **T-09 — Approved effective knowledge:** Profile registration is proposed-only. A separately granted human approves profiles/rules; proposers and services cannot approve. Versioned rules carry effective windows, supersession, scope and original proposer/approver lineage. Approved rules only are passed to handlers. - **T-11 — Required facts:** Capabilities declare required client facts. - **T-12 — Ordered lifecycle:** Source envelopes accept explicit timestamp/sequence as_of, fixture system identity, tombstone/reason and supersession. Older/conflicting versions remain immutable history; heads retain the newer accepted version. Legacy fixture arrivals are labeled legacy_arrival and make no provider-order guarantee. Removals/supersession retain links and invalidate approved work visibly. Period opening/replay re-evaluates all quarantined source types; receipts follow their referenced transaction's period while keeping their own date for matching. Locked-origin protections remain enforced during re-binding.
- **T-10 — Standing authority:** Mandates are proposed until independently approved under an authority grant. They bind rule versions, explicit period selection and timestamp freshness predicates; changed policy requires reconfirmation, and stale/missing evidence leaves occurrences awaiting_evidence. Intake wakes such approved occurrences using the persisted simulation clock. Existing fixture recurrence tests now explicitly propose/approve calendar mandates with no required fresh kinds; new tests exercise required freshness and a fixed prior-period target. No real schedule or live execution is enabled.
- **T-13 — Statement completeness:** Explicit fictional statements now carry balances, signed totals by activity, line identities, counts, provenance and sign convention. Card work checks balance/activity ties, prior opening balance and population identity, with an unreconciled-population workpaper. Legacy count/total controls alone no longer confer eligibility. The synthetic fixture's payment sign is explicitly negative and historical snapshots are not rewritten. A test-only specification adapter upgrades original reviewer control fixtures, preserving deliberately wrong totals; runtime intake never derives a statement from transactions.
- **T-14 — Dispositions and dependency controls:** Migration 11 separates current exception status from immutable history and evidence/source-hash-bound human dispositions. Closed choices resolve demonstrated duplicate, credit, settlement, split and coding paths. A propose_rule disposition creates only a proposed rule. Explicit refer_external choices keep the underlying pending/currency/missing-document blocker and require acknowledged handover; no unsupported FX, receipt or recognition conclusion is invented. Duplicate exclusion carries no proposed entry and stays explicitly held for handover. Package controls propagate; empty inventory blocks all downstream steps.
- **T-14 — Item lineage:** Historical suppliers are now computed from the item's own evidence and duplicate dependencies. A helper's unrelated receipt does not bar review of another item. Applied rule authors/approvers replace the interim all-profile-registrant rule. Relevant chart/entity/book/profile-component authors and approvers are also retained across cosmetic registrations, so configuration preparation cannot be laundered through another registrant. Provenance remains outside content identity.
- **T-15 — Proposed effects:** Card and journal preparation use one proposed-entry shape and shared mechanical validator. - **T-16 — Journal substance:** Support must be journal_support and reference that journal key. Equal date/currency/line sets flag both journals. Zero net effect by account/dimension is held. - **T-17 — Matching contract:** Receipt parameters are nullable approved rules with no default tolerance.
